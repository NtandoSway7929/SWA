# InnerMe Integration Gateway: Municipal Money pilot

**Status:** Isolated implementation branch; not deployed  
**Provider:** National Treasury Municipal Money  
**Capability:** `za.municipal_money.income_expenditure.read`

## Scope

This function exposes one authenticated, admin-only, read-only capability for the fixed `incexp_v2` cube. It is deliberately separate from the Gemini/Cloudflare model-provider router.

Request body:

```json
{
  "capability": "za.municipal_money.income_expenditure.read",
  "parameters": {
    "municipality_code": "JHB",
    "financial_year": 2026,
    "financial_period": 3,
    "amount_type_code": "ACT",
    "item_code": "0200",
    "page": 1,
    "page_size": 25
  }
}
```

Only the documented request fields are accepted. The model cannot supply a URL, host, path, HTTP method, dataset, raw `cut` expression, sort expression, or arbitrary query parameter. The adapter constructs the provider URL from a fixed HTTPS origin and fixed facts endpoint.

## Authentication

- Before deployment, add an explicit `[functions.innerme-integration-gateway]` block with `verify_jwt = true` to `supabase/config.toml`. The shared config is intentionally unchanged in this isolated implementation PR.
- The function independently validates the Bearer token with Supabase Auth `getUser`.
- The function calls `is_swayphics_admin()` using the caller's authenticated client context.
- It uses the public/anon (or publishable) API key, not the service-role key.
- The public website chat route does not call this function.

## Provider and resource controls

- Fixed origin: `https://municipaldata.treasury.gov.za`
- Fixed path: `/api/cubes/incexp_v2/facts`
- GET only; redirects are rejected.
- JSON response required.
- 8-second timeout.
- 512 KiB maximum provider response.
- Page size capped at 100; page capped at 1,000.
- Request body capped at 4 KiB while streaming; oversized bodies are cancelled before being buffered in full.
- Municipality, amount-type and optional item codes are checked against fixed `incexp_v2` member endpoints before the facts request.
- Validated member catalogues are cached in memory for ten minutes per function isolate; a missing, malformed or incomplete catalogue fails closed.
- Only fixed filter dimensions are generated by the adapter.

The host and path are not user-controlled. DNS/IP pinning and rebinding defenses are not implemented in this first adapter; that remains a security-review item before production. No model-controlled URL can be supplied, and redirects are not followed.

## Data semantics and provenance

The adapter retains the original `amount` as `amount_source_value`. When the provider returns `null`, normalized `amount` is set to zero in line with the provider documentation, and the record includes an interpretation note. The provider also warns that null or zero may indicate no further value was supplied. Consumers must not interpret a normalized zero as proof of an actual zero economic value.

The response includes:
- provider and capability identifiers;
- exact source URL and server retrieval timestamp;
- dataset and validated query;
- source field names and bounded records;
- pagination metadata;
- National Treasury attribution and terms/documentation links;
- quarterly update and source-submission limitations.

The provider's documentation describes quarterly snapshots and advises that data completeness and trustworthiness depend on municipal submissions. Its docs showed 2026 Q2 figures under completeness/integrity verification when reviewed. Check the current provider notice when interpreting results.

## Known limitations before production

1. Member validation is implemented against fixed provider catalogue endpoints and covered by injected-response tests, but a live provider metadata call and runtime test remain outstanding.
2. The provider adapter has a fixed 2020-2035 financial-year range. Revisit this bound against current provider metadata before release.
3. The fixed host/path and redirect rejection prevent model-controlled destination changes, but do not establish DNS rebinding protection.
4. Shared per-admin and project-wide quota reservation is now implemented in the feature branch. The migration is not applied and PostgreSQL concurrency/runtime verification remains outstanding.
5. No live provider call or Supabase runtime test has been run from this branch.
6. The existing isolated Supabase project `ofqofhnlzbouclvvrmzd` is currently inactive. Do not deploy until its state and cost implications are reviewed.
7. The capability is not wired into `swayphics-ai` or the InnerMe UI. It is an isolated endpoint proposal only.

## Tests

`municipal-money.test.mjs` uses injected fetch implementations and does not call the provider. It covers parameter validation, fixed catalogue membership preflight, unknown-code rejection before facts retrieval, incomplete metadata fail-closed behavior, in-isolate metadata caching, URL construction, redirect rejection, content-type and HTTP failures, payload validation, response-size limits, normalized amount semantics, provenance and sanitized errors.

The GitHub Actions validation workflow type-checks the Edge Function and runs the adapter's provider-free tests.

## Shared integration quota

The gateway now calls `innerme_reserve_integration_quota` using the caller JWT before any provider catalogue or facts request. A denied reservation returns HTTP 429 with `Retry-After`; quota-service failure returns HTTP 503 and prevents provider access. The in-flight lease is released in a `finally` path, while the request count remains consumed after upstream errors. An expired 60-second lease is the recovery mechanism if release fails.

The migration `supabase/migrations/20261104110000_innerme_integration_quota.sql` creates isolated tables and RPC helpers under the non-exposed `innerme_private` schema. It is committed to this feature branch only and has **not** been applied to any Supabase project. The staged ceilings (3/admin/minute, 15/project/minute, 30/admin/day, 100/project/day, 3 concurrent/project) count inbound gateway invocations, not individual Treasury HTTP requests. A cold invocation may make up to four provider GETs. These provisional internal safety defaults are not provider limits, require owner confirmation before database application, and do not replace checking Treasury's request allowance.

## Security review

See [`docs/innerme-integration-security-review.md`](../../../docs/innerme-integration-security-review.md) for the static security review, residual risks, release blockers, and production acceptance checklist.


**Terms-compliance blocker:** National Treasury's terms require attribution to the source and the date of publication. This facts endpoint response currently sets `attribution.publication_date` to `null`. `retrieved_at` is not the publication date. Until an authoritative publication date is obtained from provider metadata or an official notice and attached to the response, keep the pilot internal and do not use it for onward display, publication, or distribution.

## Deployment boundary

Do not deploy this function, change production secrets, create a production registry table, or wire the capability into chat without explicit owner approval after the isolated test environment is available and the security review is complete.
